# Country Search: проектные решения

## 1. Отмена устаревших запросов

### Как устроено

Состоянием поиска управляет `createSearchController` (`src/core/search-controller.ts`). У каждого запроса свой `AbortController`, ссылка на активный хранится в `activeRequest`.

1. `input(text)` вызывается на каждое событие `input` поля. Первым делом он вызывает `abortActiveRequest()`, то есть `activeRequest.abort()`. Это происходит сразу, а не когда debounce запустит следующий запрос. Поэтому пока новый текст ждет debounce, ответ на старый текст отрендериться уже не может: его промис отклонен.
2. После паузы debounce `run(query)` создает новый `AbortController` и передает его `signal` в поиск.
3. `searchCountries(query, signal)` (`src/core/search-countries.ts`) склеивает два источника отмены в один сигнал: `AbortSignal.any([signal, AbortSignal.timeout(timeoutMs)])`. Отмена пользователем приходит как `DOMException` с `name === 'AbortError'`, таймаут - как `TimeoutError`.
4. `fetch` с отмененным сигналом прерывает соединение (в Network запрос помечен `canceled`) и отклоняет промис. Ветка `try` с отрисовкой результата для этого запроса просто не выполняется.
5. В `catch` ошибку разбирает `classifySearchError` (`src/core/classify-search-error.ts`): `aborted` (наша отмена, пользователю ничего не показываем), `timeout`, `http` (`HttpError` со статусом), `network` (`TypeError` от `fetch`), `unknown`. Все, кроме `aborted`, становятся состоянием `error` с кнопкой "Повторить".
6. 404 обрабатывается еще раньше, в `searchCountries`: для countries.dev это "совпадений нет", поэтому функция возвращает `[]`, а контроллер показывает состояние `empty`. `HttpError` бросается только на остальные неуспешные статусы, потому что `fetch` на 4xx/5xx промис не отклоняет и `response.ok` проверяется вручную.

### Почему не флаг "актуальный ли это ответ"

- Флаг только прячет результат, а запрос продолжает жить: занимает соединение (у браузера их ограниченное число на домен), качает ненужный JSON и нагружает API. На медленной сети пачка устаревших запросов задерживает нужный.
- С флагом легко ошибиться. Достаточно один раз забыть проверку в новой ветке кода (например, в обработке ошибки), и устаревший ответ или его ошибка снова попадут на экран. При отмене промис отклоняется, и кода, который мог бы отрисовать устаревший ответ, просто нет.
- Отмена дает явную семантику для `catch`: `AbortError` означает "запрос больше не нужен", и ее нельзя спутать с настоящей ошибкой или таймаутом.
- Корректность проверяет тест `src/core/search-race.test.ts`. Мок `fetch` отклоняет промис с `AbortError`, если на сигнале вызван `abort()`, а ответы приходят в обратном порядке. Если убрать `abort()` из контроллера, оба теста падают, то есть тест отличает настоящую отмену от игнорирования ответа.

### Кэш и отмена (бонус)

`createCachedSearch` (`src/core/cached-search.ts`) делит один сетевой запрос между одинаковыми одновременными запросами. У каждого вызывающего свой промис, привязанный к его собственному `signal`: отмена одного отклоняет только его промис. Общий запрос отменяется, только когда его перестали ждать все (счетчик `waiting` дошел до нуля). Так кэш не ломает требование "предыдущий запрос реально отменяется": если запрос ждал только один вызывающий, его отмена прерывает и сетевой запрос.

## 2. Задержка debounce: 300 мс

Константа `SEARCH_DEBOUNCE_MS` в `src/app.ts`.

- Между нажатиями клавиш при обычном наборе проходит примерно 100-250 мс. 300 мс почти всегда покрывают паузу внутри слова, поэтому на слово `spain` уходит один запрос, а не пять.
- 300 мс - порог, после которого человек замечает задержку, но еще не считает интерфейс медленным. Индикатор загрузки показывается сразу после ввода, так что обратная связь есть и во время ожидания.

**Если убрать debounce:** запрос на каждую букву (`s`, `sp`, `spa`, ...). Больше нагрузка на API и риск упереться в лимиты, а первые короткие запросы самые тяжелые (на `s` приходят десятки стран). Отмена спасает от гонки, но сеть все равно тратится на запросы, которые тут же отменяются.

**Если сильно увеличить (1-2 с):** после ввода пользователь долго ждет и решает, что поиск не работает, или жмет Enter, которого приложение не ждет. Выигрыша почти нет: запросов и так один на слово.

Таймаут запроса - 8 с (`SEARCH_TIMEOUT_MS` в `src/core/search-countries.ts`). Обычный ответ countries.dev приходит за доли секунды, а 8 с оставляют запас для медленного мобильного интернета.

## 3. Сложность

### `mapCountryResponse` (`src/core/map-country-response.ts`)

Время - **O(L + C + B)** на одну страну, где L - число языков, C - валют, B - границ. Скалярные поля копируются за O(1), а `languages`, `currencies` и `borders` проходятся по одному разу (`map` и копирование массива). Память тоже O(L + C + B): создаются новые массивы, ответ API не мутируется.

Для выдачи из n стран контроллер вызывает функцию n раз: **O(n · k)**, где k - средний размер этих массивов (единицы элементов). На практике это линейно по числу стран.

### Кэш и дедупликация (`src/core/cached-search.ts`)

- Ключ кэша `query.trim().toLowerCase()` строится за O(q), где q - длина запроса.
- Чтение, запись и удаление в `Map` - O(1) в среднем.
- Вытеснение по LRU - O(1). `Map` хранит ключи в порядке вставки. При попадании ключ удаляется и вставляется заново, поэтому первым в `Map` оказывается давно не использованный, и `cache.keys().next()` находит его за O(1) без сортировки.
- Дедупликация: поиск запроса в полете в `inFlight` (`Map`) - O(1). Подписка и отписка вызывающего - O(1): один обработчик `abort` и счетчик.
- Память: O(M · R), где M - лимит записей (`maxEntries`, по умолчанию 50), R - размер ответа. Без лимита кэш рос бы бесконечно за долгую сессию.

История (`src/core/search-history.ts`): `add` - O(H), где H - лимит истории (8). Фильтрация дублей и обрезка списка.

## 4. Принципы чистого кода

- **Single Responsibility.** Каждый модуль делает одно дело: `debounce.ts` только откладывает вызов, `search-countries.ts` только ходит в сеть, `map-country-response.ts` только преобразует данные, `classify-search-error.ts` только разбирает ошибки, `search-controller.ts` управляет состоянием. UI-модули в `src/ui/` только рисуют.
- **Разделение логики и представления.** Все в `src/core/` не трогает DOM, это проверяет правило ESLint `no-restricted-globals` для `src/core/**` (`eslint.config.js`). Контроллер сообщает о состоянии через `onChange`, а `src/app.ts` решает, как его нарисовать.
- **Чистые функции.** `mapCountryResponse` и `classifySearchError` без побочных эффектов, тестируются на заготовленных JSON (`src/core/fixtures/`) без сети.
- **Dependency Injection.** Контроллер получает функцию поиска параметром (`SearchControllerOptions.search`), поэтому в тестах подставляется управляемый мок, а в приложении кэширующая обертка (`src/main.ts`). История получает хранилище параметром (`HistoryStorage`) и не зависит от `localStorage`.
- **Open/Closed.** Кэш (`createCachedSearch`) оборачивает любую `SearchFn` с той же сигнатурой. Контроллер и `searchCountries` для этого не менялись.
- **Явные состояния вместо флагов.** `SearchState` - размеченное объединение (`idle`, `loading`, `results`, `empty`, `error`). Невозможные комбинации вроде "загрузка и ошибка одновременно" не выражаются типами. `switch` в `renderStatus` (`src/ui/status-view.ts`) и `failureMessage` проверяется на полноту TypeScript.
- **Говорящие имена и константы.** `SEARCH_DEBOUNCE_MS`, `SEARCH_TIMEOUT_MS`, `NOT_FOUND = 404`, `abortActiveRequest`, `classifySearchError` вместо магических чисел и общих имен.
- **Fail fast и явные ошибки.** `HttpError` хранит статус, `searchCountries` бросает ее сразу после проверки `response.ok`. Неизвестные ошибки не теряются, а попадают в `unknown` и показываются пользователю.
- **Безопасная работа с DOM.** Разметка создается через `h()` (`src/ui/dom.ts`) на `createElement` и `textContent`. `innerHTML` и `insertAdjacentHTML` запрещены правилом `no-restricted-properties`.
